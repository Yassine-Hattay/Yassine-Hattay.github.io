🧠 Thesis Insights & Pareto Front Analysis

⚠️ What's Measured vs. What's Extrapolated
Directly measured (our own llama-bench data): Ryzen 5 5600H (laptop), Pentium Gold G5420 (desktop), Jetson Nano. A Raspberry Pi 3B was attempted but produced zero usable benchmark rows.

Never tested locally: Raspberry Pi 4B and Pi 5. Any numbers shown for these devices come from third-party sources and are marked as such below.

MoE models: Staged in the harness but never benchmarked to completion on any device. The "bytes-per-token" MoE advantage shown here is a theoretical prediction derived from dense-model bandwidth mechanics, not a measured result.

This calculator: A client-side prediction tool implementing the roofline/USL model. It does not run any benchmarks. For devices other than the three calibrated above, treat outputs as informed estimates, not measurements.
💡 The Quantization Format Paradox (Legacy x86)
Thesis Finding: On legacy CPUs lacking AVX-512/VNNI (e.g., Pentium G5420), smaller K-quant formats like Q3_K_M or Q4_K_M are actually slower than the older, larger Q4_0 format. The complex bitwise unpacking required for K-quants bottlenecks the CPU. Q4_0 maintains ~98.8% accuracy relative to F16 and is the strictly Pareto-dominant choice for older hardware.
🧠 Mixture-of-Experts (MoE) on Edge Devices
Thesis Finding: On GPUs, MoE is a capacity play. On CPUs, MoE is a bandwidth play. Because generation is memory-bandwidth-bound, an MoE model (e.g., 14B total, 2.7B active) only streams the active experts per token. This drastically reduces B_total in the Roofline equation, allowing MoE models to bypass the sub-1 tok/s bottleneck that traps dense 7B models on bandwidth-starved hardware.

⚠️ Note: This is a theoretical prediction derived from our dense-model bandwidth data. No MoE model was benchmarked to completion on our hardware.
📉 Flash Attention & KV Cache on CPU
Thesis Finding: Flash Attention (-fa 1) is designed for GPU HBM/SRAM hierarchies. On CPU, the L3 cache handles attention state differently. Empirical sweeps showed Flash Attention is neutral at short context, but causes a 3× performance regression at 15K context depths on CPU. Always use -fa 0. Similarly, KV-cache quantization is a net loss on compute-rich CPUs (dequantization costs more cycles than the bandwidth saved), but flips to a net win on ultra-low bandwidth edge devices.
📊 External Reference Points (Third-Party — Not Our Measurements)
These are published third-party numbers included for context only. They were NOT run with our harness or our model checkpoints. The only edge device we actually measured ourselves is the Jetson Nano.

• Raspberry Pi 5 (8GB): ~2–3 tok/s on 7–8B-class Q4 models.
Sources: Jeff Geerling's ai-benchmarks repo (github.com/geerlingguy/ai-benchmarks); LocalAIMaster 2026 survey (localaimaster.com/blog/llm-raspberry-pi-5)

• Raspberry Pi 4B (4GB): No independently verified source found for 7B generation throughput — treat as an open gap, not an oversight.

• Raspberry Pi 3B (1GB): No independently verified source found for generation throughput — treat as an open gap.

• Jetson Nano (4GB): ~0.04 tok/s on 7B (flat, bandwidth-saturated at 1 thread); ~3 tok/s on 1.5B (scales linearly).

📖 Glossary

Token

A chunk of text, roughly ¾ of a word. "Hello world" is 2 tokens. Speed is measured in tokens per second (tok/s).

Prefill (pp512)

The "reading" phase. The model processes your entire prompt before it starts writing. Speed here depends on raw CPU compute power.

Generation (tg128)

The "writing" phase. The model produces text one token at a time. Speed here depends mostly on memory bandwidth, not CPU power.

KV Cache

The model's short-term memory of the conversation so far. Grows as the conversation gets longer. Must fit in RAM.

Quantization

Compressing the model's numbers to use less memory. Q4 = 4 bits per number (small, fast, slightly less accurate). Q8 = 8 bits (bigger, slower, more accurate).

Roofline Model

A way to predict the maximum possible speed based on two limits: how fast the CPU can compute, and how fast memory can deliver data. Whichever limit is hit first determines your actual speed.

USL (Universal Scalability Law)

A formula that predicts how speed changes as you add more CPU threads. It accounts for the fact that threads can get in each other's way, sometimes making things slower.

Retrograde Scaling

When adding more CPU threads actually makes the model slower, not faster. Happens when memory bandwidth is the bottleneck and extra threads just add contention.

Flash Attention

A GPU optimization that reduces memory traffic. On CPU, it's neutral at best and can be a 3× slowdown at long context. Always disable it on CPU (-fa 0).

MoE (Mixture of Experts)

A model architecture where only a subset of parameters are used per token. Theoretically faster on CPU because less data is read from memory per word. Untested locally.

Pareto Front

The set of "best possible" configurations where you can't improve speed without sacrificing quality or memory (and vice versa). This tool helps you find your point on that front.
